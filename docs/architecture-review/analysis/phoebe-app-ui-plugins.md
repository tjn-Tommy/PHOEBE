# Panel report — Composition root, UI, plugin authoring

Scope: `phoebe/app/bootstrap.py`, `phoebe/ui/{app,bridge,main_window}.py`, `phoebe/plugins/*`, `examples/run_sim_demo.py`, `config/sim.toml`, `pyproject.toml`. Supporting files read to verify call chains: `core/{gateway,task_manager,bus,events,plugin,di,config,worker,writer,device_manager,controller,sweep}.py`, `instruments/protocols.py`, `refactor.md` §§12–18.

## 1. Responsibility map

**`app/bootstrap.py` — composition root.** `build_runtime()` (bootstrap.py:42-76) is an async constructor that must run on the loop that will own the system: it builds `EventBus` (binding it to the running loop, bootstrap.py:53), `WorkerPool`, `ControllerFactoryRegistry` (+ `register_builtin_factories`), then `DeviceManager` and awaits `device_manager.start(connect=True)` — so all controllers are created, connected, and identity-verified before a window exists. It then builds `TaskManager` (which snapshots the DI role/kind maps at construction, task_manager.py:189-193), starts suspenders, and wraps the `TaskManager` in a `Gateway`. The result is an `AppRuntime` dataclass holding every subsystem plus the loop (bootstrap.py:25-34). `AppRuntime.shutdown()` (bootstrap.py:36-39) does exactly three things: stop suspenders → `device_manager.shutdown()` (cancel reaper, `disconnect()` every controller, device_manager.py:80-88) → `worker_pool.stop_all()`. **It does not touch active runs** (see Issue 1). `LoopThread` (bootstrap.py:79-108) owns the dedicated asyncio loop on a daemon thread; `stop()` calls `loop.stop()` cross-thread and joins — it never cancels pending tasks or closes the loop.

**`ui/app.py` — process entry.** Ordering (app.py:33-58): `load_builtin_plugins()` → `load_app_config()` → start `LoopThread` → `build_runtime` on it with a 120 s timeout, aborting (and stopping the thread) before Qt if any device fails identity check → create `QApplication`, `UiEventBridge.start(bus, loop)`, `MainWindow` → one-shot `device_manager.health_check_all()` scheduled directly on the loop (app.py:52) → `app.exec()` → on exit: `bridge.stop()` → `runtime.shutdown()` (30 s timeout) → `loop_thread.stop()`.

**`ui/bridge.py` — the only core→Qt path.** `UiEventBridge.start()` schedules a pump coroutine on the loop that subscribes to six topics with `DROP_OLDEST` and re-emits every `BusEvent` through `pyqtSignal(object)` (bridge.py:36-48); cross-thread emission is queued onto the Qt thread. `stop()` cancels the pump future; the `finally` unsubscribes on the loop thread (bridge.py:44-45).

**`ui/main_window.py` — panels.** `DevicePanel` seeds its table straight from `config.instruments` (main_window.py:58-62) and updates rows from `device_health` events. `RunControlPanel` holds two hand-written forms (`TpaForm.command = "start_tpa_run"` main_window.py:101; `GridForm.command = "start_grid_scan"` main_window.py:119) that build plain-dict payloads. Command path: form → `submit_requested` → `MainWindow._submit` → `gateway.submit_threadsafe(envelope, loop)`; the `concurrent.futures` done-callback fires on the loop thread and hops back via the `_ack_received` signal (main_window.py:303-308). Acks are handled non-modally (statusbar + log, main_window.py:310-326); the acked `task_id` is stored and used for `pause/resume/cancel` built-ins. Event path: one `_on_event` dispatcher string-matching `event_type` (main_window.py:329-351): `run_state` drives Start/Pause/Resume/Cancel enablement with the `final` gate (`final = not event.state.is_terminal or event.reason == "final"`, main_window.py:336), matching the TaskManager's post-cleanup rebroadcast (task_manager.py:370-372); `progress` drives the bar and appends `metrics["peak_dbm"]` to the metric plot (main_window.py:340-344); `data_pointer` previews go to pyqtgraph `setData` (main_window.py:345-347). The UI imports only `core.config`, `core.events`, `core.gateway` (main_window.py:37-39) — no Controller/Driver — and holds references to `Gateway`, the loop, `AppConfig`, and live `BusEvent` pydantic objects; never to controllers.

**Plugins.** `@register(plugin_id=...)` mutates the process-global `plugin_registry` at class-definition time; `register_class` scans `dir(cls)` for methods marked by `@on_command` and refuses duplicate commands (plugin.py:53-78). Discovery is deliberate: `load_builtin_plugins()` is an explicit import list (plugins/__init__.py:8-10), not entry-point scanning. Dispatch chain: `Gateway.submit` → `TaskManager.dispatch` → `validate_boundary(spec.config_type, cmd.payload)` (task_manager.py:204) → `DependencyResolver.resolve` over the entrypoint signature (`Depends` default + Protocol annotation → kind → role/binding/unique-by-kind, di.py:77-111) → atomic lease acquisition → `_execute` injects controllers as keyword args (task_manager.py:322, 331). `tpa_multiplier.py` is the reference plugin: 80 lines, checkpoint per step, settled `display_pattern`, arrays via `ctx.writer.append_array`, previews via `trace.preview()` (256-point downsample, domain/spectrum.py:81-86). `spectrum_grid.py` delegates to the declarative `grid_scan` helper (sweep.py:31-53).

**`examples/run_sim_demo.py`** is the headless golden path: same `load_builtin_plugins` + `build_runtime` + `gateway.submit` path as the UI, plus a bus watcher; the only privileged call is `task_manager.wait(task_id)` (run_sim_demo.py:47, 55).

**`pyproject.toml`**: core deps only pydantic/numpy/h5py/loguru (pyproject.toml:10-15); `visa`/`daq`/`ui`/`parquet` extras (17-21). Lazy-import discipline holds at package roots: `phoebe/__init__.py` and `phoebe/ui/__init__.py` are empty of imports.

## 2. Strengths

- **Correct two-way thread bridge.** Both crossings match spec §12.5 exactly: in via `run_coroutine_threadsafe` (gateway.py:52-55), out via a Qt signal only (bridge.py:43), and the ack round-trip cleverly reuses a second signal so the future callback never touches widgets from the loop thread (main_window.py:303-308). The bus's cross-thread assert (bus.py:113-119) makes violations loud in dev mode.
- **Core-before-Qt startup with fail-fast identity verification** (app.py:36-43; device_manager.py:66-78): a misconfigured instrument aborts before any window exists, and the loop thread is torn down on the failure path.
- **The final-rebroadcast Start gate is actually implemented end to end**: terminal state re-published with `reason="final"` only after stop/unstage/writer-close/lease-release (task_manager.py:349-372), and the UI keeps Start disabled until that rebroadcast (main_window.py:190-199, 335-337). This closes the 423-race by protocol rather than by sleep.
- **No modal dialogs on async paths** (main_window.py:310-315) — rejections ("423 locked") are routine statusbar events; the only `QMessageBox` guards local form parsing (main_window.py:182-184), which is Qt-synchronous and safe.
- **Plugin authoring surface is genuinely small and rule-compliant**: both shipped plugins contain zero locks, zero sleeps, zero Driver imports; devices arrive typed as Protocols; explicit-import discovery (plugins/__init__.py) avoids import-side-effect magic while keeping `@register` ergonomics.
- **Single validation choke point respected by the UI**: panels send raw dicts; `validate_boundary` at dispatch (task_manager.py:204) is the one place payloads are checked, and a bad `GridForm` payload (e.g. empty levels vs `min_length=1`, spectrum_grid.py:18) surfaces as a clean rejected ack.
- **The demo and the GUI drive the identical Gateway path**, so the headless CI story and the interactive story cannot drift at the command layer (run_sim_demo.py:40-47 vs main_window.py:291-308).

## 3. Issues

**Issue 1 — No graceful termination of active runs at shutdown. Severity: Critical (real hardware) / High (sim).**
Evidence: app.py:54-58 runs `runtime.shutdown()` immediately after `app.exec()` returns; `AppRuntime.shutdown` (bootstrap.py:36-39) never cancels or waits for active `TaskManager` tasks; `DeviceManager.shutdown` only calls `disconnect()` (device_manager.py:80-88), and real controllers' `disconnect()` merely closes the transport (tek_awg5204/controller.py:70-72, rs_rto6/controller.py:81-83) — no `stop()`/`safe_state()`. Then `loop_thread.stop()` (bootstrap.py:106-108) halts the loop with the run coroutine pending, so the run's `finally` block (task_manager.py:349-372) — writer flush/close, `baseline_post`, lease release, final event — never executes. Scenario: user closes the window mid-run. On real hardware the AWG/SLM are left in whatever state they were in (outputs on) while their sessions are closed under a coroutine mid-`await`; the run directory has no `baseline_post.json`, metrics.parquet compaction never happens, and `artifacts.h5` is left unclosed (per-append `flush()` at writer.py:237 limits but does not eliminate corruption risk). Nothing in the exit path even checks `task_manager.active_tasks()`.

**Issue 2 — UI command surface is hardcoded and duplicates plugin schemas, with already-divergent defaults. Severity: High.**
The registry can enumerate commands (`PluginRegistry.commands()`, plugin.py:83-84) but the UI never asks; instead each plugin needs a hand-written Qt form with a `command` class attribute (main_window.py:101, 119). Form defaults have already drifted from the contract defaults: UI `max_steps=50`, points `501` (main_window.py:105, 88) vs `TPAConfig` `max_steps=100`, points `1001` (tpa_multiplier.py:31-34). `TPAConfig.trace_name` and `mask_spot_check_every` aren't exposed at all, and `trace_name` is additionally dead in the plugin itself — defined at tpa_multiplier.py:35 but hardcoded to `"TRA"` at line 54. Impact: every new plugin means editing `main_window.py`; schema drift is silent because dispatch-time validation accepts any valid payload regardless of what the form claimed.

**Issue 3 — Config binding tables are inert because plugins hardcode roles. Severity: High (silent misbehavior).**
`di.py:88` gives `Depends(role=...)` priority over `[plugins.*.bindings]`. Both shipped plugins pin roles in code (`Depends(role="primary_slm")`, tpa_multiplier.py:48-49; spectrum_grid.py:33-34), so the binding tables in config (sim.toml:78-84) are dead configuration. Scenario: an operator points `slm = "secondary_slm"` in the TOML to rebind an experiment to another device; nothing changes, no warning is emitted. The spec's whole disambiguation ladder (§7.2) is bypassed by its own reference plugins.

**Issue 4 — Backpressure/throttling is defeated at the bridge; previews are unthrottled. Severity: Medium.**
Only `ProgressEvent` goes through `ThrottledEmitter`; `DataPointerEvent` (which carries the preview) is published on every `emit_progress` call (task_manager.py:127-132). The bridge pump drains its bounded `DROP_OLDEST` queue eagerly and re-emits into Qt's *unbounded* queued-connection event queue (bridge.py:41-43), so the drop policy can never engage as long as the pump keeps up — the boundedness lives on the wrong side of the boundary. Today the sim OSA's simulated sweep time paces the loop, but a fast acquiring instrument (scope/DAQ streaming) would push pyqtgraph `setData` at loop rate and grow the Qt queue without limit. The spec's publisher-side throttling principle (§9.3) is implemented for progress only.

**Issue 5 — Dead `log` topic: plugin logs never reach the UI. Severity: Medium.**
`LogEvent` is defined (events.py:110-116), subscribed by the bridge (`DEFAULT_UI_TOPICS`, bridge.py:21-23), and handled by `MainWindow` (main_window.py:350-351) — but nothing anywhere publishes one (grep: only definition and the union). `ctx.log` is a bound loguru logger going to `experiment.jsonl` only (task_manager.py:303-308). Impact: the "Events" panel shows only gateway acks and state transitions; `ctx.log.info("TPA encoding loop starting")` is invisible in the GUI. A loguru→bus sink is missing.

**Issue 6 — UI process reaches around the Gateway; health is checked exactly once. Severity: Medium (spec-rule tension + missing capability).**
app.py:52 calls `runtime.device_manager.health_check_all()` directly. This is arguably composition-root code, but there is *no* gateway command for health/inventory/reconnect, so any out-of-process frontend cannot trigger it at all. `health_check_all` has exactly one caller in the codebase (app.py:52); no periodic poll exists (the only background task is the lease reaper, device_manager.py:185-199). Scenario: a device drops mid-session — the device table shows "ok" forever. Related: the bus's retained-event snapshot keeps only the last event per topic (bus.py:128), so a late subscriber to `device_health` sees one instrument's health, not five — the snapshot mechanism under-delivers for multi-entity topics, which is why app.py needs the direct sweep in the first place (subscribe happens at bridge.start, app.py:47, before the sweep at :52, so the current GUI is fine — the design gap bites reconnecting clients).

**Issue 7 — Single-task assumptions in MainWindow event filtering. Severity: Medium.**
`run_state` events pass the filter when `self._task_id is None` (main_window.py:335), and `progress`/`data_pointer` events are not filtered by task at all (main_window.py:340-347). `_task_id` is only ever overwritten by the next ack — never cleared on terminal. Under `dispatch_policy = "queue"` (or any second command source), progress and metric points from a different task interleave into the same plot, and `reset_metrics()` fires at submit time (main_window.py:292) — before the ack — so a rejected 423 submission wipes the plot of the still-running run. Also the metric plot is hardcoded to `peak_dbm` (main_window.py:342): grid scans emit no metrics (sweep.py:51-52), so their metric plot is silently empty.

**Issue 8 — Import-linter contract is claimed but does not exist. Severity: Medium.**
main_window.py:6 asserts "the import-linter contract (§18 rule 9) holds", and refactor.md:1436 (rule 13) requires CI-enforced layering. There is no `[tool.importlinter]` in pyproject.toml (pyproject.toml:1-30), no import-linter dev dependency (pyproject.toml:22), and no CI workflow directory in the repo root. The discipline is currently voluntary; the docstring is misleading about enforcement.

**Issue 9 — Demo fragility. Severity: Low.**
run_sim_demo.py:50-55 never checks `ack.accepted` for the second command; if rejected, `task_manager.wait(None)` raises `KeyError: None` (task_manager.py:290). The watcher's subscription is cancelled but never `unsubscribe`d (run_sim_demo.py:28-57), and the final listing iterates all historical run dirs, not just this session's (run_sim_demo.py:59-62).

**Issue 10 — LoopThread/loop hygiene for embedding. Severity: Low.**
`LoopThread.stop()` neither cancels pending tasks nor calls `loop.close()` (bootstrap.py:106-108); `WorkerPool.stop_all()` joins with a 5 s timeout and abandons stuck threads (worker.py:111-116, 196-201). Harmless for a process that exits, a leak for any long-lived host (test harness, web server). Also `build_runtime`'s partial-connect failure leaves earlier-connected transports open (device_manager.py:50-57; app.py:39-43 only stops the thread).

**Issue 11 — No installable entry point. Severity: Low.**
No `[project.scripts]`/`[project.gui-scripts]` for `phoebe.ui.app` (pyproject.toml:5-23); the documented invocation is module-path-dependent.

## 4. Extension pain points

**New plugin.** Author must know: subclass `Plugin`, set `config_type`, decorate with `@register`/`@on_command`, annotate deps with a registered Protocol + `Depends`, then (a) add an import to `load_builtin_plugins` (plugins/__init__.py:8-10 — no entry-point discovery), (b) hand-write a Qt form + tab + payload builder in main_window.py, (c) know that `Depends(role=...)` disables TOML rebinding (Issue 3), and (d) know that only `peak_dbm` plots (Issue 7). Steps b–d are undocumented tribal knowledge.

**New instrument kind.** The preview pipeline is spectrum-shaped end to end: `DataPointerEvent.preview` is a `TracePreview` with `x_nm`/`y_dbm` fields (events.py:53-65) and `PlotPanel` hardcodes nm/dBm axes (main_window.py:212-215). A scope waveform or DAQ stream has no preview vehicle — you must add a new event type to the closed union (events.py:120-130), a bridge topic, and a `MainWindow._on_event` branch.

**Reconnection/fault recovery.** `connect_instrument` exists (device_manager.py:59-64) but nothing calls it after startup; no gateway command, no UI affordance, no health poll (Issue 6). Recovering a dropped VISA session today means restarting the application mid-shift.

**Web (Vue/Tauri) frontend — concrete rework list.** The bones are good (closed `GatewayEvent` union with `seq` ordering, `command_id` correlation, per-subscriber bounded queues), but: (1) the Gateway is submit-only — no query surface for command list, config schemas, device inventory, run history, or task state; the Qt UI gets all of these in-process (`AppConfig` into `DevicePanel`, main_window.py:51-63; `device_manager` from app.py:52), none of which crosses a network. (2) Nothing serializes events today — the bridge emits live pydantic objects (bridge.py:30, 43) and the `GatewayEvent` union (events.py:120-130) has zero non-test consumers; the promised JSON Schema export (§3.6/§13.3) does not exist (no `model_json_schema` call in the tree). (3) Retained-per-topic snapshots can't rebuild client state on reconnect (Issue 6). (4) The final-rebroadcast Start-gating rule is client-side business logic (main_window.py:190-199, 336) that every frontend must re-derive; it belongs in a server-side "dispatchable" flag or event field. (5) Preview/coalescing policy must move server-side per-client (Issue 4). (6) UNCERTAIN: whether `CommandEnvelope.issued_by` is meant to carry client identity for multi-client arbitration — nothing reads it today (gateway.py:29; no other references found); multi-client `_task_id` ownership (Issue 7) would need a real session model.
