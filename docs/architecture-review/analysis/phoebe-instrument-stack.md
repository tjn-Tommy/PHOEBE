# Panel report — Instrument stack (Transport / Driver / Controller / Worker / Protocols / Registry / Sim)

## 1. Responsibility map

**`phoebe/core/transport.py`** defines the `ScpiTransport` Protocol (open/close/write/query + binary variants, transport.py:17-30) and shared IEEE-488.2 block encode/parse helpers (transport.py:33-57). The async methods are explicitly "post to worker and await" wrappers, not true async I/O (transport.py:1-8).

**`phoebe/core/worker.py`** — `BlockingDeviceWorker` is one daemon thread per device with a `queue.Queue` job loop (worker.py:47-160). `call()` creates an `asyncio.Future` on the calling loop, posts `(fn, args, kwargs, fut, loop)`, and the thread resolves it via `loop.call_soon_threadsafe` with done-guards (worker.py:77-85, 150-170). An `initializer` runs first on the thread itself — used to pin DLL handles (worker.py:130-137); `pump=True` switches to a 5 ms poll that drains Win32 messages between jobs (worker.py:24-44, 139-147). `WorkerPool.for_device` enforces one-worker-per-instrument, recreating dead workers (worker.py:173-194).

**Transports.** `VisaScpiTransport` (transports/visa.py) lazily imports pyvisa inside `_open_blocking` (visa.py:57-80), maps VISA timeouts to `InstrumentTimeoutError` (visa.py:98-108), and routes every operation through `worker.call` (visa.py:38-54). `TcpScpiTransport` (transports/tcp.py) is line-oriented CR/LF SCPI with an injectable `on_open` handshake hook (tcp.py:40-101) used by the AQ637X telnet-style login (yokogawa_aq637x/driver.py:27-44). `MockScpiTransport` (fnmatch rules + command log) and `TranscriptReplayTransport` (JSONL replay) are the test doubles (transports/mock.py:17-120).

**Drivers.** All four SCPI/SDK drivers are genuinely pure protocol translation: AQ637X (yokogawa_aq637x/driver.py:47-126), RTO6 (rs_rto6/driver.py:25-337), AWG5204 (tek_awg5204/driver.py:20-194) contain zero locks, zero `asyncio.sleep`, zero lifecycle logic — only command formatting and reply parsing. The NI-DAQ driver is synchronous by contract with `nidaqmx` imported inside methods (ni_daq/driver.py:38-45, 85-87). The one exception is the Santec DLL driver, which contains `time.sleep(0.5)` polling and a 60 s deadline inside `set_video_mode` (santec_slm200/driver.py:196-206) — defensible since it must run as one atomic worker job on the DLL thread, but it is a blocking wait living in a driver (see Issues). `csvio.py` implements the Santec CSV frame format with strict validation both ways (csvio.py:18-62).

**Controllers.** `InstrumentController` (core/controller.py:58-105) provides the `asyncio.Lock` op-lock, a per-controller `CapabilityRegistry`, abstract lifecycle (`connect/disconnect/identity/health/snapshot`), default no-op `stage/unstage`, and abstract `stop/safe_state`. The five real controllers are structurally parallel: capability-protocol methods take the op-lock, call driver methods, and build domain models; e.g. the OSA's `acquire_trace` = configure + N×(sweep, poll, download) under one lock (yokogawa_aq637x/controller.py:145-172), the scope's arm-poll-download (rs_rto6/controller.py:161-182), the AWG's delete→upload→playlist→assign deployment (tek_awg5204/controller.py:124-170). `stop()` deliberately bypasses the lock in each (aq637x:138-139, rto6:121-122, awg:112-113). The SLM controller adds settle semantics (`asyncio.sleep(settle_ms)` inside the lock, santec_slm200/controller.py:186) and an op-lock-aware keepalive task (controller.py:221-239).

**Registry & factories.** `register_builtin_factories` registers `(kind, vendor, model)` → build function, with three Yokogawa model strings enumerated (instruments/registry.py:19-32). `ControllerFactoryRegistry.create` routes `backend == "sim"` to per-kind sim factories before consulting the key table (core/factory.py:65-81). Build functions match on the connection union from config (e.g. tek_awg5204/controller.py:204-218) and obtain workers from `deps.worker_pool` — the SLM passes `pump=True, initializer=driver.load` (santec_slm200/controller.py:253-254).

**Protocols.** Five `runtime_checkable` Protocols, one per kind, registered in an explicit protocol→kind table for DI (instruments/protocols.py:35-103, core/di.py:26-34). The DI resolver maps `Depends` annotations to kinds and roles to instrument ids (di.py:68-112); `TaskManager._execute` then injects raw controller objects into the plugin entrypoint (core/task_manager.py:321-331) and runs the stage → entrypoint → stop/safe_state/unstage cleanup chain (task_manager.py:328-356).

**Sim.** `SimContext` holds one mutable `current_mask`; `TpaPhysicsModel` maps mask coherence → spectrum peak and detector volts (sim/context.py:34-61). `sim/controllers.py` implements all five kinds directly against `SimContext`, sharing it via `deps.sim_context("tpa", SimContext)` (controllers.py:266-273) — sim controllers bypass driver and transport layers entirely.

## 2. Strengths

- **The layering is real, not aspirational.** Drivers own only vocabulary; controllers own only semantics; transports own only wire+thread mechanics. You can diff `AQ637XDriver` against the refactor.md §4.3 example and it matches in kind. No driver imports asyncio primitives; no controller touches sockets/pyvisa; grep confirms lazy-import discipline is intact (visa.py:60-66, ni_daq/driver.py:40-45).
- **The worker model correctly solves DLL thread affinity.** Initializer-on-thread + `pump=True` + "compound DLL sequences as one job" (worker.py:59-74, santec_slm200/driver.py:189-190) is exactly the shape the Santec SDK needs, and exception propagation via done-guarded futures (worker.py:150-170) is careful about cancelled awaiters.
- **Abortable acquisition idiom.** Both OSA and scope use write-then-poll (`SINGle;*OPC` + `*ESR?` poll; `:INIT` + operation-event poll) with a loop-time deadline and `context.ensure_not_cancelled()` inside the wait (rs_rto6/driver.py:206-216, rs_rto6/controller.py:207-223, yokogawa_aq637x/controller.py:174-184) — cancellation genuinely reaches into hardware waits, and no blocking `*OPC?` can wedge a worker.
- **Sim physics closes the loop.** Mask coherence monotonically drives the OSA peak and detector voltage (sim/context.py:34-61), so optimizer plugins are meaningfully testable offline, including settle simulation (sim/controllers.py:110) and average-count-dependent noise (context.py:50-54).
- **Uniform controller shape.** The five controllers differ only where the hardware differs; a new instrument author can pattern-match. Options models per instrument give strict two-stage config validation (e.g. yokogawa_aq637x/controller.py:46-54).
- **Test doubles at the right layer.** `MockScpiTransport` logs the exact command stream so L1 tests assert SCPI formatting (tests/test_drivers_l1.py:42-99), and the transcript replayer defines the L2 contract (mock.py:75-120).

## 3. Issues

**H1 (High) — A real RTO6 can never pass identity verification.** The factory key demands `vendor = "rohde-schwarz"` in config (instruments/registry.py:27, config/sim.toml:45), `_verify_identity` requires that exact token to appear as a substring of `vendor+model+raw` from the device (core/device_manager.py:70-78), but the controller's own documented `*IDN?` is `"ROHDE&SCHWARZ,RTO6,..."` (rs_rto6/controller.py:87-96). `"rohde-schwarz"` is not a substring of `"rohde&schwarz"`, and no normalization exists anywhere (core/config.py:56-64 passes vendor through verbatim). No vendor string satisfies both the registry lookup and the identity check simultaneously. Trigger: first real-hardware connect of the scope; sim mode masks it entirely. UNCERTAIN only in that the live IDN string could differ from the code comment.

**H2 (High) — VISA binary downloads can truncate at any 0x0A byte.** `_open_blocking` sets `read_termination = "\n"` on the resource (visa.py:76-79); pyvisa translates that into an enabled termchar, which `read_raw()` honors, and `_query_binary_blocking` uses `write` + `read_raw` (visa.py:130-137). A float32 waveform block statistically contains byte `0x0A` every ~256 bytes, so RTO6 `CHANnel:DATA?` downloads (rs_rto6/driver.py:251-260) would return truncated blocks and raise "IEEE block truncated" (core/transport.py:53-56) almost every time. UNCERTAIN — backend-dependent (some VISA implementations suppress termchar for raw reads); confirm by one real read or a pyvisa-sim test. The conventional fix territory (suppress termchar around binary reads) is untested because no L1 test covers this path.

**H3 (High) — TCP binary read: infinite busy-loop on connection close, and unmapped timeouts.** In `_query_binary_blocking`, the header/length loops do `header += sock.recv(2 - len(header))` with no empty-chunk check (tcp.py:163-172): if the peer closes, `recv` returns `b""` forever and the worker thread spins at 100 % CPU holding the device's only thread — every later `worker.call` queues behind it forever, with no error surfaced. Additionally `socket.timeout` in those loops escapes raw instead of being mapped to `InstrumentTimeoutError` as the text paths do (compare tcp.py:137-142). Trigger: device drops the link mid-block — a realistic LAN event.

**H4 (High) — No reconnection or fault recovery exists anywhere in the stack.** `connect_instrument` is called only from `DeviceManager.start` (device_manager.py:50-64; grep shows no other caller). Transports do not invalidate state on error: TCP `_send`/`_recv_line` raise but keep `self._sock` (tcp.py:118-146), VISA keeps `self._inst` after any error (visa.py:110-120), so after a transient outage every subsequent call fails against a dead handle until process restart. Health checks publish `DeviceHealthEvent`s (device_manager.py:224-240) but nothing consumes "error" status to act. This blocks the stated long-experiment goal: an overnight optimizer dies permanently on one glitch.

**H5 (High for the primary use case) — Santec frame display leaks a multi-MB temp CSV per frame.** `display_frame` writes a `NamedTemporaryFile(delete=False)` CSV and never deletes it (santec_slm200/driver.py:176-184; grep confirms no `unlink` anywhere in `phoebe/`). A 1920×1200 grid is ~9 MB of ASCII; keepalive re-sends multiply it (controller.py:232-234). A 10k-iteration optimization run leaks ~90 GB into %TEMP% — disk exhaustion in normal operation — and every display pays a full CSV serialization + DLL file-read round trip.

**M1 (Medium) — `stop()` bypasses the op-lock but not the worker FIFO.** The base-class contract says stop "MUST be callable concurrently with an in-flight operation" (core/controller.py:96-100), but for every SCPI device `stop()` is just another job on the same single-thread queue (visa.py:44-48 → worker.py:77-85). Its latency is bounded by the longest single blocking call — e.g. an AWG multi-MB `write_binary` or a query stuck until the 30 s configured timeout (config/sim.toml:52,75). Not hardware-unsafe here, but the documented guarantee is stronger than the implementation; for the SLM, `stop()` is an explicit no-op (santec_slm200/controller.py:155-158).

**M2 (Medium) — Role-based DI never checks kind; injection never checks protocol conformance.** The role path in the resolver maps role→instrument without comparing that instrument's kind to the parameter's protocol kind (core/di.py:88-95), and `_execute` injects raw controllers with no `isinstance` against the (runtime_checkable, protocols.py:35) Protocol (task_manager.py:321-331). A TOML typo like `osa = "primary_slm"` passes dispatch, acquires leases, writes a manifest, and fails mid-run with `AttributeError`. Silent misbehavior of the fail-fast goal (refactor.md §7.2's "fail fast at dispatch").

**M3 (Medium) — Health/snapshot I/O bypasses the op-lock, contradicting the atomicity claim.** `get_health`/`get_snapshot` issue driver queries lock-free (yokogawa_aq637x/controller.py:111-131, rs_rto6/controller.py:99-118, tek_awg5204/controller.py:87-105) while each file's header claims "two tasks' SCPI can never interleave" (yokogawa_aq637x/controller.py:5-6). Per-query atomicity at the worker level prevents reply mismatch, but a periodic `health_check_all` (device_manager.py:224-230) interleaves device-state commands into the middle of an acquisition's configure/poll sequence. `stage()` also aborts lock-free (aq637x controller.py:133-135).

**M4 (Medium, spec rule 12) — sim/real option asymmetry.** `SimPatternModulator` validates options with base `SlmOptions` (sim/controllers.py:97), which is `extra="forbid"` (core/contracts.py:42-44), so a real SLM config using `Slm200Options` keys (`keepalive_interval_s`, `ensure_dvi_on_connect`, santec_slm200/controller.py:60-66) crashes when flipped to `backend="sim"` — the "same config runs under sim" invariant (refactor.md §18 rule 12) fails. Conversely, the other four sim controllers never validate options at all (sim/controllers.py:45-52), so option typos rejected in real mode pass silently in sim.

**M5 (Medium) — Worker/shutdown edge cases.** (a) The `loop.call_soon_threadsafe` result-relay is outside any try (worker.py:154-158); if the event loop is closed first, the `RuntimeError` kills the worker thread, and since transports hold a direct worker reference captured at build (visa.py:20-28, tcp.py:46-54), every subsequent call hangs on a future nobody will resolve — `WorkerPool.for_device`'s dead-worker revival (worker.py:189-193) never helps existing transports. (b) `stop()` joins with a 5 s timeout and ignores failure (worker.py:111-116). (c) Exceptions relayed to already-cancelled futures are silently discarded with no logging (worker.py:168-170) — a hardware error during cancellation vanishes.

**M6 (Medium, UNCERTAIN) — Message pump starves during long jobs.** The pump runs only between jobs and when idle (worker.py:141-160); `set_video_mode` occupies the thread for up to 60 s of `time.sleep(0.5)` polling (santec_slm200/driver.py:196-206) with zero `PeekMessage` — the spec's §12.4 loop pumps every 5 ms regardless. Whether the DLL's Ctrl path needs pumping is unverified; the display window presumably does. Confirm against vendor docs or by observing window responsiveness during a mode switch.

**M7 (Medium) — L1/L2 test tiers are mostly unbuilt.** Only the AQ637X driver has unit tests (tests/test_drivers_l1.py:42-99). RTO6 SCPI formatting/header parsing, AWG deployment ordering, IEEE-block round-trips (the H2/H3 paths), NI-DAQ, and Santec CSV I/O have none. `TranscriptReplayTransport` exists (mock.py:75-120) but there is no recording transport anywhere, so transcripts can never be produced — the L2 regression tier is unreachable as shipped.

**L1 (Low) — Protocol surface inconsistencies.** `PatternModulator.set_enabled` lacks `InvocationContext` (protocols.py:52) so cancellation can't reach it; `AnalogInput.read_sample` and `Oscilloscope.monitor_sample` duplicate "scalar monitor" semantics with incompatible request types (protocols.py:61-78), so a plugin cannot abstract over "any detector"; the OSA defines no `unstage()` to restore continuous sweep despite the base-class docstring naming exactly that example (core/controller.py:92-94, absent in yokogawa_aq637x/controller.py).

**L2 (Low) — Registry brittleness.** Exact-string model enumeration (registry.py:19-24) means each new AQ637x letter suffix is a code change; the ControllerKey vendor string is doubly load-bearing (factory lookup + identity substring, see H1).

**Sim fidelity limits (fact, for the lead's test-strategy picture):** sim ignores OSA sensitivity/reference level (sim wavelength axis and peak only, context.py:41-48), scope trigger/decimation/`values_per_sample` (controllers.py:156-172), and `SimWaveformGenerator` couples to nothing in `SimContext` (controllers.py:216-254) — AWG output has no physical effect, so AWG-in-the-loop experiments validate only call sequencing. No sim can inject timeouts/disconnects, so none of H2–H4 is testable offline today.

## 4. Extension pain points

- **New instrument kind** touches ≥6 files by convention (protocols.py + di registration, domain models, driver, controller, registry, sim controller + `_SIM_CLASSES`, controllers.py:257-263) — mostly mechanical, but nothing enforces that the sim and real controllers implement the same protocol (no conformance test harness), and per-controller boilerplate (identity parsing of `*IDN?`, health-as-identify, snapshot try/except) is copy-pasted across four controllers (e.g. aq637x:98-109 vs awg:74-85 vs rto6:85-97) — a shared `ScpiIdentityMixin`-shaped gap.
- **Reconnection/fault recovery** will be painful to retrofit: transports don't own "am I healthy" state, controllers cache `_identity`/`_connected` flags independently, and the keepalive/lease/health layers have no hook to trigger reconnect; H4 plus the stale-worker-reference problem (M5a) means recovery needs coordinated changes in transport, worker pool, and DeviceManager.
- **Web (Vue/Tauri) frontend** is largely insulated from this layer (good), except: capability discovery for a generic UI relies on `CapabilityRegistry.list_ids` while the protocol methods (the primary surface: `acquire_trace`, `display_pattern`...) are *not* capabilities and have no serialized invocation path — a remote frontend can reach `SLM_DISPLAY_GRAYSCALE` (santec controller.py:47-57) but not `display_pattern` without new plumbing.
- **Notable idea worth preserving:** the `on_open` handshake hook (tcp.py:50, yokogawa driver.py:27-44) is the right pattern for vendor login quirks without contaminating the generic transport; a symmetric "on_error → invalidate" hook is the natural seam for the missing reconnect logic.
